# Quickstart

Three instructions. One CPI call. That's the entire integration.

**Guard program ID (devnet):** `BmevGCa642U4Zs1462wN1QQ3N921dFUijW52ULtDpqhb`

---

## Step 1 — Add the Guard as a CPI dependency

```toml
[dependencies]
anchor-lang = "0.32.0"
trana       = { version = "0.1", features = ["cpi"] }
```

## Step 2 — Add six accounts to your instruction struct

```rust
use trana::cpi::accounts::Enforce;
use trana::program::Trana;
use trana::Policy;

#[derive(Accounts)]
pub struct Withdraw<'info> {
    // ... your existing accounts ...

    // ── Trana: 6 accounts ────────────────────────────────────────────────────
    pub guard_program: Program<'info, Trana>,

    #[account(
        mut,
        seeds  = [b"2fa", owner.key().as_ref()],
        bump,
        seeds::program = guard_program.key(),
        constraint = trana_registry.enabled @ YourError::PasskeyNotRegistered,
    )]
    pub trana_registry: Account<'info, trana::TwoFactorRegistry>,

    /// CHECK: Solana Instructions sysvar
    #[account(address = anchor_lang::solana_program::sysvar::instructions::ID)]
    pub trana_instructions: UncheckedAccount<'info>,

    #[account(seeds = [b"config"], bump, seeds::program = guard_program.key())]
    pub trana_config: Account<'info, trana::TranaConfig>,

    /// CHECK: treasury address validated inside trana against config
    #[account(mut, constraint = trana_treasury.key() == trana_config.treasury)]
    pub trana_treasury: UncheckedAccount<'info>,

    pub system_program: Program<'info, System>,
}
```

## Step 3 — Call enforce

```rust
pub fn withdraw(ctx: Context<Withdraw>, amount: u64) -> Result<()> {
    trana::cpi::enforce(
        CpiContext::new(
            ctx.accounts.guard_program.to_account_info(),
            Enforce {
                registry:       ctx.accounts.trana_registry.to_account_info(),
                owner:          ctx.accounts.owner.to_account_info(),
                instructions:   ctx.accounts.trana_instructions.to_account_info(),
                config:         ctx.accounts.trana_config.to_account_info(),
                treasury:       ctx.accounts.trana_treasury.to_account_info(),
                system_program: ctx.accounts.system_program.to_account_info(),
            },
        ),
        // Guard reads `amount` from this instruction at byte offset 0 (after discriminator).
        // If amount < limit, enforce() is a no-op — no proof required.
        Policy::Limit { param_offset: 0, limit: 1_000_000_000 },
    )?;

    // your withdrawal logic here — only reached if passkey approved (or amount < limit)
    Ok(())
}
```

That's the entire program-side integration.

## Step 4 — Build the transaction

Every protected instruction must be preceded by exactly two guard instructions:

```
ix[N-2]: secp256r1 precompile    ← native P-256 signature verification (SIMD-0075)
ix[N-1]: trana::record_proof     ← WebAuthn binding data (authenticatorData, cdJSON)
ix[N]:   your_program::withdraw  ← calls trana::cpi::enforce() internally
```

`ComputeBudget` instructions can be prepended — they shift all indices up and the guard adjusts. For multiple protected instructions in one transaction, include a separate `(secp256r1, record_proof, protected)` triplet for each.

```typescript
const tx = new Transaction({ recentBlockhash, feePayer: owner })

// ComputeBudget before the triplet is fine
tx.add(ComputeBudgetProgram.setComputeUnitLimit({ units: 400_000 }))

// The triplet — must be contiguous, in this order
tx.add(buildSecp256r1Ix(pubkey, sig, webAuthnEValue))
tx.add(buildRecordProofIx(guardProgramId, expiry, cluster, policy, authData, cdJSON))
tx.add(withdrawIx)
```

See `tests/guard.ts` for the full reference implementation of `buildSecp256r1Ix`, `buildRecordProofIx`, and `computeIntentHash`.

## Policies

```rust
// Always require a passkey — no conditions
Policy::Require

// Require when the u64 at param_offset bytes (after discriminator) >= limit.
// Guard reads the value directly from the instruction — cannot be faked.
Policy::Limit { param_offset: 0, limit: 1_000_000_000 }

// Require until slot is reached; free after
Policy::NotBefore { slot: activation_slot }

// Require after slot passes; free before
Policy::NotAfter { slot: expiry_slot }
```
